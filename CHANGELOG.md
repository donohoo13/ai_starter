# Changelog

Template releases, newest first. Each entry carries three parts: **what** changed, **why**, and **adaptation notes** for instances whose posture diverges from the shipped defaults (compliance regimes, external trackers, collapsed monorepos). A release is a git tag (`vX.Y.Z`) on `main` matching the entry heading; the `sync-template` skill in an instance walks unapplied entries oldest-to-newest (later releases assume earlier ones landed) and negotiates each into the instance's own posture. In an instance this file is template residue: `project-init` stamps the template lineage into `CLAUDE.md` from the top entry here, then deletes this copy.

## v4.2.0 — 2026-10-02

- **What**: a seventh skill, `preflight`, proves a finished feature branch is production ready and then opens its PR.
  It gates on a non-default branch, a clean tree, and a settled intent (argument, the branch's spec, or one line from the user, never transcripts).
  It syncs by rebasing an unpublished branch or merging the default branch into a published one, and never force-pushes.
  It dispatches two new read-only agents in fresh contexts: `code-reviewer` reviews the diff against the intent and scopes each finding `branch` or `trunk`, and `docs-reviewer` finds statements across `docs/**`, every `README.md`, `CLAUDE.md`, `.claude/`, the changelog head, and in-code help that the diff made false.
  The session fixes a finding only when it has few dependents, is verifiable in the session, and leaves the intent unchanged, with a `/tdd` reproduction first for behavioral fixes and one commit per fix; a single scoped re-review checks the fixes; everything else stops at one report for the user to fix, defer, or skip.
  Lint, format, typecheck, and the full suite must pass, flaky tests are surfaced rather than rerun, and pushing and the PR wait on the user's yes.
  The PR body fills the template's Validation and Review sections, CI gets one repair round, and nothing is ever merged.
  `CLAUDE.md` Skills, the root `README.md`, and the skills `README.md` name the skill and agents.
  `.github/PULL_REQUEST_TEMPLATE.md` grows from Summary and QA to Summary, Validation, Review, and QA, generic enough for a human-written PR.
  `.github/workflows/checks.yml` is rewritten to one job on every PR and every push to `main`, with no path filters: `jdx/mise-action` installs the pinned toolchain, the pnpm store is cached, then `pnpm install --frozen-lockfile`, `format:check`, `lint`, `typecheck`, `test`, and a new root `test:scripts` that runs every `scripts/test/*.battery.mjs`.
  `scripts/test/env-matrix/` and its Docker-based CI step are deleted.
  A new `mise.toml` carries no versions, only `idiomatic_version_file_enable_tools = ["node", "pnpm"]`, so mise reads Node from `.nvmrc` and `devEngines.runtime` and pnpm from `packageManager`; the README quickstart becomes `mise install` then `pnpm install`, and `check-install.mjs`, `doctor.sh`, and `javascript-typescript.md` name mise alongside nvm.
  `template-dev.md` names `pnpm test:scripts` as the battery entry point.
  `package.json` `version` to 4.2.0.
- **Why**: `implement-spec` ends at human QA and nothing between QA and a reviewable PR held a standard, so a branch reached reviewers with whatever slop, stale docs, or unrun suites the build left behind.
  The flow follows [no-mistakes](https://github.com/kunchenguid/no-mistakes)' pipeline (review, test, document, lint, push, PR, CI) without its disposable worktree, background daemon, permission bypass, or self-driven pushes: a clean-tree gate replaces worktree isolation, and the user's yes replaces an automatic push.
  Reviewers are agents rather than reference files so their tool list is read-only, which keeps a reviewer from quietly fixing what it should report; the docs review is its own agent because "did the code make a doc false" is a different search than "is the code wrong".
  Published history is never rewritten because a lease protects the remote, not a teammate's local branch, so the skill stays safe in a team repo.
  The old CI ran only when tooling files changed and never ran format, lint, typecheck, or tests, so most PRs got no checks and `preflight`'s CI step had nothing to watch; the new job is the independent check of what `preflight` claims to have run.
  The env matrix proved pnpm provisioning across mismatched, Node-less, and musl Docker images, an edge real projects rarely hit, at the cost of the slowest step in CI.
  mise's idiomatic version files are off by default, so without the project `mise.toml` a teammate's mise silently supplies its own global Node and pnpm; reading the existing pins instead of repeating them adds no new drift site, at the cost of one `mise trust`, which `mise install` performs and linked worktrees inherit.
- **Adaptation notes**: the skill and agents are additive; copy the skill directory and both agent files, then add the name-drops.
  An instance with no PR template gets a body under the same Summary, Validation, Review, and QA headings.
  CI deliberately stops at the 80% case; an instance adds its own OS or Node matrix, coverage thresholds, E2E, security scanning, a `build` step, previews, and release automation, and makes `checks` a required status check in branch protection.
  An instance not using mise swaps `jdx/mise-action` for `actions/setup-node` with `node-version-file: .nvmrc` plus `pnpm/action-setup`, and may delete `mise.toml`; one that relied on the env matrix for musl images keeps its copy.
  An instance whose CI needs more than one repair round raises the cap in the CI section; one whose host is not GitHub replaces the `gh` calls with its own CLI.

## v4.1.0 — 2026-10-02

- **What**: `CLAUDE.md` Markdown rule flips from one continuous line per bullet to one sentence per physical line, with a multi-sentence bullet continuing on indented lines and untouched passages left unreflowed; `curate-context` drafting guidance changes from "single-line bullets" to "one sentence per line" to match.
  `CLAUDE.md` Development gains a bug-fix rule: reproduce the bug the way a user hits it and confirm the repro fails for the reported reason before changing code.
  `tdd` gains a Bug fixes section placing that repro as a failing test at the lowest seam that exhibits the bug, climbing to end-to-end only when no lower seam can show it, and the skills `README.md` blurb names it.
  `implement-spec` Workspace relaxes its first bullet: building on `main` is allowed when the user dictates it, and switching branches in a shared checkout is cautioned rather than forbidden outright.
  A new path-scoped rules file, `.claude/rules/agent-facing-output.md` (`scripts/**`, `.claude/hooks/**`), sets five output floors for anything an agent runs: a definitive outcome line including empty and no-op cases, failures that name the next command, no interactive prompts, summary-first bounded output, and idempotent mutations; `CLAUDE.md` Development and the skills `README.md` rules paragraph name it.
  `package.json` `version` to 4.1.0.
- **Why**: one sentence per line makes a prose diff name the sentence that changed instead of a whole paragraph-length bullet, which is the review cost that mattered more than cut-and-move atomicity.
  The bug-fix rule exists because a fix written before a faithful repro tends to patch a symptom; the principle lives in `CLAUDE.md` where every session sees it, and the seam mechanics live in `tdd` where test placement is already decided.
  The `implement-spec` change hands the main-branch call back to the user, who may run a solo or throwaway build where a branch is ceremony.
  The output floors are distilled from [AXI](https://axi.md/), whose author-run benchmarks show agent-shaped CLI output cutting turns and cost against raw CLIs and MCP servers; the payload's own scripts already followed most of them unwritten, so a project's new scripts had no way to learn the convention.
  AXI's TOON output format, ambient session hooks, and no-argument-shows-content behavior were left out: a nonstandard format buys little over JSON or plain text, and a per-session hook taxes every session's context.
- **Adaptation notes**: the Markdown rule applies to new writing only; existing docs need no reformat, and an instance that prefers the old atomic-bullet convention keeps its line and skips the `curate-context` wording change together, since the two must agree.
  `.prettierrc` already sets `proseWrap: preserve`, so the sentence breaks survive formatting; an instance that changed that setting restores it before adopting the rule.
  An instance running Git branch protection or a stricter worktree posture keeps its own `implement-spec` Workspace bullet.
  The output rules file is additive; an instance whose scripts live outside `scripts/` adds those paths to its frontmatter.

## v4.0.0 — 2026-09-29

- **What**: the guard-hook suite drops from four to two and the permission registry stops matching substrings across whole commands. **`guard-main`** walks git subcommands in order and tracks state the command itself changes: `git checkout -b`/`switch -c`, a switch to an existing branch, and `git tag` creates and deletes earlier in the command update the branch and tag set later subcommands are judged against, so `git checkout -b feat && git commit` and `git tag -a vX.Y.Z && git push origin vX.Y.Z` pass while `git checkout -- file && git commit` on main still blocks. It also blocks any push whose refspec writes to or deletes the default branch from any branch (`main`, `+main`, `x:main`, `HEAD:refs/heads/main`, `:main`, `--delete main`), which replaces the seven `Bash(git push*main*)` deny globs, now deleted. **Deny registry**: `Bash(*wrangler*)` and `Bash(*deploy*)` become `*wrangler deploy*`, `*wrangler pages deploy*`, `*wrangler versions deploy*`, `*wrangler publish*`, `*pnpm deploy*`, and `*run deploy*`, with `Bash(*wrangler*--remote*)` added to `ask`. **Dev servers**: `guard-dev-server` and its battery are deleted; `pnpm dev` now runs `scripts/dev/node-dev-server.mjs`, which exits 0 with the running pid when `.logs/dev-server.pid` names a live process and otherwise starts `turbo dev` (extra args pass through), mirroring stdout and stderr into `.logs/dev-server.log` (truncated per start, `.logs/` gitignored). The `CLAUDE.md` rule flips from "do not run dev servers" to "start them only through `pnpm dev` as a background task". **Skills**: `skill-creator` and `guard-skill-edit` are deleted; the discipline moves nearly verbatim into `.claude/rules/skill-authoring.md` (`paths: '.claude/skills/**'`) and its reference to `docs/skill-quality.md`. `CLAUDE.md`, both READMEs, `curate-context`, and `template-dev.md` are rewritten to match, the latter collapsing its two tag-publishing bullets into one. **Tests**: `scripts/test/guard-main.battery.mjs` (34 cases through the registered prefilter against a throwaway clone and worktree) and `scripts/test/node-dev-server.battery.mjs` (fake `turbo` on PATH) replace the dev-server guard battery in CI. **Formatting**: `.prettierrc` drops to `printWidth: 100` plus the Markdown `proseWrap: preserve` override, taking Prettier's defaults otherwise (double quotes the visible change), and a new `.editorconfig` sets UTF-8, LF, two-space indent, final newline, trailing-whitespace trim outside Markdown, and a 100-column limit; the whole tree is reformatted to match.
- **Why**: measured against transcripts, the costliest guard was not a hook but the deny globs: Claude Code matches a `Bash(...)` pattern's `*` across `&&` and pipes, so `git push -u origin feat && gh pr create --base main` hit `Bash(git push* main *)`, and `echo '## wrangler'`, `ls apps/*/wrangler*`, and `mkdir deploy` hit the wrangler and deploy globs, each denial costing a retry loop. `guard-main`'s own defect was evaluating the branch before the command ran, so the ordinary branch-then-commit chain blocked on main; the push-destination check belongs in the hook, which already splits segments, rather than in globs that cannot. `guard-dev-server` enforced a policy that made every server a round-trip to the user and 250 lines of pattern matching that still missed script-spawned servers; the real needs were no duplicate servers and shared visibility, and a single sanctioned entry point meets both for human and AI starts alike, so no hook is needed. `skill-creator` was guidance, not a procedure: it ran no tooling and disclaimed testing its own output, and it needed a transcript-grepping hook to get loaded at all, while a path-scoped rule loads on every `Edit` of a skill file by the harness itself. A skill earns its place with a real procedure, such as an eval loop that runs test prompts in fresh subagents; bring one back when that exists.
- **Adaptation notes**: an instance takes `guard-main.mjs` wholesale and deletes the seven push globs in the same change, since the hook now covers them; an instance on GitHub branch protection keeps that as the server-side backstop. An instance that deploys through something other than wrangler or a `deploy` script adds its own anchored deny (`Bash(*vercel deploy*)`, `Bash(*fly deploy*)`) rather than a bare-word glob. An instance whose root `dev` script is not `turbo dev` edits the spawn in `node-dev-server.mjs`; one that wants servers to stay user-only keeps its copy of `guard-dev-server` and skips that part. An instance with its own skills keeps them untouched and adopts the rule file; a session that invoked `/skill-creator` by habit now finds no command, so mention the rule in the instance's onboarding notes if the team used it. The formatting change is optional: an instance keeping single quotes skips `.prettierrc`, and one adopting it runs `pnpm format` once in its own commit so the reformat stays out of feature diffs.

## v3.1.0 — 2026-09-13

- **What**: a new path-scoped rules file, `.claude/rules/html-tables.md`, carrying the markup and CSS floor for a plain `<table>`, distilled from MDN's "Styling tables" lesson and bent to the payload's existing conventions. **Markup**: tabular data only, a `<caption>` naming what one row is, `<thead>`/`<tbody>` with `<tfoot>` reserved for totals, every header a `<th>` with `scope`, widths on the `<th>`, and no nested tables, presentational attributes, or inline styles. **Styling**: `table-layout: fixed`, `border-collapse: collapse`, and `width: 100%` on the table; shared cell `padding` from the spacing scale with `vertical-align: top`; text left and numerics right with headers aligned to their column; one row-separation device, a hairline divider by default and zebra striping only when the table is wide enough to need it; headers distinguished by weight or surface token rather than size; `caption` styled as a label above the data; `%` or `ch` column widths and a single `overflow-x: auto` wrapper. `CLAUDE.md` Frontend and UI and the skills `README.md` rules paragraph name the file. `package.json` `version` → 3.1.0.
- **Why**: the payload's only table guidance was the three-bullet "Data tables" section in `ux-standards.md`, which governs grid behaviour (sticky headers, virtualization, row actions) and says nothing about the markup and CSS beneath it, so a session building an ordinary table had no floor to hold and reinvented borders, alignment, and header treatment each time. MDN's lesson is the reference because its quick-tips list is the consensus baseline; three of its sample values were adapted rather than copied. Its `px` margins and letter-spacing become `em`, since `frontend-styling.md` reserves `px` for hairline borders. Its `caption-side: bottom` becomes `top`, because a caption is announced first by screen readers and reads as the table's label there. And its zebra striping becomes the alternative to `ux-standards.md`'s hairline dividers rather than a second device stacked on them, so the two files state one rule instead of two. The `<th>` scope and no-inline-style bullets are the same accessibility floor `ux-standards.md` already holds, restated at the element where a session would break it.
- **Adaptation notes**: additive; an instance copies the file and adds the two name-drops. An instance shipping no UI deletes it with the other frontend rules. An instance whose styling system was swapped at init reads the spacing-scale and surface-token references as its own tokens; nothing in the file is Tailwind-specific. An instance that already stripes rows and draws hairlines picks one, since the file forbids both on one table. The email override is stated in the file, so an instance that deleted `transactional-email.md` removes that sentence.

## v3.0.0 — 2026-09-10

- **What**: the process suite collapses from twenty-one skills and eleven agents to seven skills and one agent, and every survivor is rewritten to a hard budget of 5000 characters of body excluding frontmatter, with `ux-standards.md` held under 3000. **`sdd`** replaces the whole grilling family (`grill-me`, `grilling`, `grill-engineer`, `grill-product`, `grill-design`, `grill-initiative`, `grill-research`, `ground-brief`): one interview, one question at a time, biggest decision first, recommendation attached, running the product, design, and engineering lenses in parallel at a stated 25/15/60 attention split rather than as separate sessions, and always exiting by writing a spec to `docs/specs/NNN-<slug>.md` at `status: ready` from `sdd/assets/spec-template.md` (Product Requirements, Design Requirements when a surface is touched, Engineering Requirements with vertical slices that each carry a done-when and an Architecture section that states what happens to the existing implementation, Evidence, References with Sources, Out of Scope, Rejections); `sdd/references/example-spec.md` is the worked example. A trailing `†` on a slice check, constraint, rejection, or exclusion marks a decision the user drove, stated in the ask or held under interview, with a one-line legend under the title present only when a mark is; a recommendation the user merely accepted stays unmarked, and `sdd` resumed on a spec leaves `†` items standing. **`implement-spec`** replaces `implement-task`: gate on a ready spec, one confirm for a worktree via `gwt-add.sh` or a plain non-main branch, then per slice plan, `/tdd`, validate, commit, audit, and a land step of full suite plus human QA before `status: done`. The demolition pass (`demolition-planner`, `demolition-executor`, the `incumbent:` key, Demolition and Survivors sections, the connection map) is gone; in its place the spec's Architecture names whether the existing implementation is kept, extended, or stripped first, and `implement-spec` carries one line on why a rewrite tends to land cleaner with the old shape deleted before the first slice, judged against the spec. **`tdd`** and **`stage-for-commit`** are condensed to budget with their behavior intact; `tdd` drops its `CONTEXT.md` and ADR references. **`skill-creator`** and its `guard-skill-edit` hook stay, the skill condensed to budget with the 3500-character body rule and the self-contained rule added and its grilling-exit and fork-points references removed. **`brand-init`** and `BRANDING.md` stay: the skill is condensed to budget as a one-time initialization that writes the doc directly and offers to delete itself afterwards, with its grilling, domain-modeling, and curate-context references removed; the doc's preamble names no consuming skill and `CLAUDE.md` tells every session to read it before a brand or surface decision. **`curate-context`** stays, condensed to budget, keeping attribution, the admission bar, routing, drafting, and the brand identity blast-radius report, and losing its domain-modeling hand-off, grill-lens carve-outs, template-feedback channel, and project-init exception. **`research-analyst`** survives, retargeted to `sdd`. Deleted outright with every reference: `capture-task` and the `docs/tasks/` template, `diagnose`, `domain-modeling` (with `CONTEXT.md`, `ARCHITECTURE.md`, and ADRs as concepts), `review-board` with its nine agents and checklists, `ship-pr`, `project-init`, `sync-template`, and `template-feedback` with `docs/adr/0001`. `ux-standards.md` is rewritten to its floors, composition, forms, feedback, and table rules with the closed-to-growth and load-mechanism prose removed; `frontend-styling.md` and `transactional-email.md` lose their init references. `CLAUDE.md`, the root `README.md`, the skills `README.md`, `template-dev.md`, the PR template, `gwt-add.sh`, and the rules-frontmatter battery are rewritten to the suite that exists now. `package.json` `version` → 3.0.0.
- **Why**: the suite had grown past what a session could hold or a maintainer could keep coherent: `grill-design` alone was 26k characters, `implement-task` 22k, `curate-context` 20k, against an original intent of about 3k each, and the growth was mostly gating, chaining, and hand-ups between skills that only made sense if every path through the suite was followed. The user of this template is an engineer who also has to make the product and design calls, and splitting those into separate sessions with separate artifacts (briefs, design artifacts, initiatives, ADRs, a domain glossary) produced ceremony without better specs. Folding the three lenses into one interview with a stated attention split keeps the product and design questions that actually change the engineering outcome and drops the rest. Domain modeling and the demolition machinery were the two largest sources of verbosity relative to their value; the demolition finding it guarded against (old code patched around rather than deleted) is real, so it survives as a judgment line in `implement-spec` rather than a two-agent pass. Making every skill self-contained, with no skill recommending the next, puts sequencing back with the user, who knows when they are ready for the next step. The `†` mark exists because a spec otherwise reads as one voice: a build session or a reviewer cannot tell which lines the user set from which the interview proposed, and the user's own lines are the ones a later session must not trade away while resolving something else.
- **Adaptation notes**: this is a rebase, not a diff. A project carrying `docs/tasks/` files at `status: scoped` or `in-progress` rewrites each into a spec by hand: Context and Problem become Product Requirements, Design decisions become Architecture, Test strategy folds into each slice's done-when, and `incumbent: replace` becomes an Architecture line naming what is stripped first. A project with `docs/designs/` artifacts keeps them as reference material and cites them from a spec's References; nothing reads them anymore. Projects that relied on `sync-template` now read this changelog by hand from the version they started at; that is the whole update channel from here on. Specs written before the `†` mark stay valid unmarked; add marks only when a spec is next reopened, and only from memory of who decided, never by guessing.

## v2.8.0 — 2026-08-10

- **What**: three findings from instance issue #42, resolved as two payload edits and four manifest entries. `implement-task`'s **Fallback and teardown** section is restated rather than patched, because the edit reframes what the passage is for: it read as the list of terminal alternatives to the worktree path, and it now opens by stating that a settled answer and a temporary obstacle arrive at the same moment and look alike. A **declined confirm** stays settled and stands for the whole task, with one carve-out — a confirm declined while a detour is open is a blocked user taking the cheapest way out of a question nobody asked, so the obstruction clears and the confirm is put again afterwards. An **absent `gwt-add.sh`** is settled the same way. An **`EnterWorktree` that fails after `gwt-add.sh` already succeeded** is split out as its own case, because the branch and the worktree both exist by then and git refuses that branch in the main checkout while the worktree holds it: the session names the worktree path, hands the user `git worktree remove <path>` to release the branch without deleting it, and falls back onto that same branch, since `gwt-remove.sh` would take a landed pre-flight commit with the branch. **Every other obstruction is a detour rather than a destination** — name what is in the way, say what clears it, wait, then re-enter at the step that raised it, Step 2 for a worktree that exists and cannot be used and Step 4 for one that does not exist yet. A **main checkout parked on this task's own branch is not an obstruction**, since a previous session took the fallback and built there. And an obstruction the user says cannot clear this session is **`BLOCKED`**: report what is in the way and what would clear it, then stop at the current status, because a session waiting indefinitely and a session that finished look identical from outside. Section 2 Step 4's checkout verification gains its second ground: a new branch seeds from the checkout's HEAD, and an existing branch is refused outright while the main checkout holds it. The skills `README.md` blurb carries the same three-way distinction. Step 3's doc pre-flight is **unchanged**: it hands the commit to the user on the default branch, which is correct wherever a human can commit there. Where an org ruleset routes every change through a pull request it is not, and that case lands in `project-init/references/fork-points.md` under Branch model as a new entry beside the `stage-for-commit` lever it sits outside of — the pre-flight inlines that skill's behavior rather than invoking it, so the existing entry never reaches it. The entry moves the destination and **keeps every branch switch the user's**, because Section 2's second bullet forbids the session switching branches in a shared checkout and a tailored Step 3 that has the session do it contradicts the section it sits in. Three more manifest entries land with it: the worktree-isolation entry is corrected to Section 2 Steps 2 and 4 (it credited Step 2 with creating the worktree), the demolition entry now cites `implement-task`'s demolition dispatch section rather than a step number, and the `frontend-styling.md` entry gains the instruction to carry the theme-values-by-name rule into whatever styling system replaces the pruned Tailwind block. Separately, `.claude/rules/frontend-styling.md` takes three bullet restatements. **Units and scaling** names the dynamic viewport units with the safe default first: any element sized to the full viewport height takes `svh`, or `dvh` when that element has no fixed or sticky descendant, never `vh`. The **Tailwind** semantic-tokens bullet keeps its absolutes and gains the ground it never had — component files consume theme values by name and carry no raw palette value and no `dark:` variant, every colour including alpha is a semantic colour token, and every non-colour value that differs between themes (opacity, mask, filter, transform) is a custom property declared in the app's CSS file alongside those tokens with a value under each theme selector, read at the call site as `opacity-(--watermark-strength)`. And the **verification bullet** is scoped to what it actually governs, naming both failure modes: a colour class with no `--color-*` mapping is silently dropped, while a custom property consumed with the `(--var)` form is read straight through, so an undefined one falls back to the property's initial value rather than disappearing. `package.json` `version` → 2.8.0.
- **Why**: an instance built a surface-bearing task and hit all three findings in one session. The Fallback finding is the one with a mechanism worth naming. Its reported symptom was a whole build running in the main checkout, and the cause was not the blocker the instance hit but the shape of the section it read afterwards: two bullets, both written for a settled answer, and no third state. `implement-task`'s Step 4 already told a session with the checkout parked elsewhere to surface that and wait without saying what to do next, so the section's terminal-looking alternative was the only stated path forward. That path is reachable with no compliance posture at all — the user was on a branch is the ordinary case — which is why it is a payload fix rather than a tailoring entry. The protected-branch half went the other way, and the reasoning behind that split is worth stating because half of it was wrong on the first pass. The claim was that the git ordering constraint is unreachable in the template as shipped, so writing it into the payload would mean adding both an accommodation and the rule the accommodation makes necessary. This release's own review board falsified it: a declined confirm puts the derived branch in the main checkout, a later session resumes the same task, and Step 4 takes `gwt-add.sh`'s attach path, where git refuses outright. The constraint is reachable with zero compliance posture, which is why Step 4's verification gained a second ground here rather than staying in the manifest. The protected-branch destination still stays a lever, on the part of the argument that survived: `guard-main` gates the AI rather than the human, `CLAUDE.md` Git Control is addressed to the AI, and `stage-for-commit` states outright that `main` is expected and correct, so the shipped text has no defect — it has a posture it does not hold, and `fork-points.md` is the machinery for exactly that. The board's other reversal ran the same way. The `dark:` bullet was first rewritten as a pure positive instruction, which deleted the only prohibition verb in the payload while supplying the ground it lacked; a session shipping `dark:border-white/20` would have read a description of what component files do and reasoned that a hairline is not a theme value, reproducing the very split this finding was filed about. Ground and absolute now sit in the same bullet, per `CLAUDE.md`'s rule to write rules as absolutes and document exceptions at point of use. The two styling findings share a root: the file modeled colour as the only thing that varies by theme and desktop as the only viewport that matters, correct for what it covered and silent past its edge. The reporting session avoided both defects by reasoning past the file, which is not a mechanism the template can rely on. The `dark:` bullet is the more instructive, because the instance's review board split on it — one seat flagged a single-use theming utility as violating the 3+ reuse threshold and the chair rejected the finding on the ground that the threshold was not the governing constraint, and both readings were defensible from a bullet that stated no ground at all. So the fix supplies the missing why instead of carving an exemption into the threshold: with the varying value declared as a custom property beside the colour tokens, the call site consumes it by name, and no single-use utility, no `dark:` override, and no exception to the reuse rule is needed. Two alternatives were dropped — exempting single-use theming utilities, whose boundary is a judgment about a utility's reason for existing, and allowing `dark:` for non-colour properties, which puts theme variation in the two places the rule exists to prevent. The viewport bullet's default was inverted for the same class of reason the board keeps finding: the first cut named `dvh` first and gated the safe branch on whether chrome "would jitter", a prediction no authoring session can check without a running device, so the cheap reading won and the cheap reading was the unsafe one. The trigger is now a property of the markup.
- **Adaptation notes**: wording-only across one skill, one rules file, and the manifest; instances apply the payload edits as-is. **An instance whose default branch is protected does not need the manifest to act on this**, because the lever is restated here: derive the task branch as Step 1 does, then hand the user the commands — they create that branch in the main checkout so the untracked docs ride along, commit there, and return the checkout to the default branch before Step 4 runs. Keep every one of those switches the user's, since the session is forbidden to switch branches in a shared checkout. - **Why**: v1.0.1 correctly ordered instances to delete `nodeVersion` and move the pin to `devEngines.runtime`, and its notes even anticipated the key — but `nodeVersion` was the only thing holding `engineStrict` harmless, so for any instance that took pnpm's documented advice ("use `nodeVersion` and `engineStrict` in a `pnpm-workspace.yaml` file at the root of the project") the instruction was the direct cause of the brick rather than merely silent about it. With both keys set, the engines check runs against the version pnpm pretends and passes; with `nodeVersion` gone it runs against the developer's ambient Node, before pnpm switches to the `devEngines` runtime, so it refuses the very install that would have downloaded the pin. Measured in an instance on pnpm 10.34.1, macOS/APFS, ambient Node 24.17.0 against a 22.22.3 pin: `engineStrict: true` fails `pnpm install` and `pnpm typecheck` identically with `ERR_PNPM_UNSUPPORTED_ENGINE`, so it is every pnpm command and not just the install, and provisioning the runtime first does not help because the check precedes the switch every time; `engineStrict: false` installs, fetches 22.22.3, and reports it from both `pnpm exec node -v` and `pnpm run` while the shell stays on 24.17.0. pnpm's settings page claims a project's own `engines` field fails the install "regardless of this configuration", which cost a wrong diagnosis before the measurement contradicted it — the notes now say so explicitly, because the next reader will find that line too. The same non-failure is observable in this repo on a different pnpm patch: with `engineStrict` unset, `pnpm format:check` on pnpm 10.32.1 with ambient Node 24.17.0 against an `engines.node` of `>=26.5.0 <27` prints `WARN Unsupported engine` and runs the script, so the doc line is wrong on 10.32.1 as well as 10.34.1. Why the check passes with `engineStrict` off is unknown; the measurement is what both the notes and the guard encode, and neither states a mechanism it cannot demonstrate. Amending v1.0.1 in place is the right mechanism here rather than a workaround: `project-init` deletes an instance's copy of this file and `sync-template` reads the template's tip through `git show template/main:CHANGELOG.md`, so an instance that has not yet applied v1.0.1 gets the corrected notes automatically, while one already past it is exactly who this entry exists for. The `check-install.mjs` half earns its fifteen lines on a narrow but real case, and its limit is stated in the file rather than left for the next reader to discover: it cannot fire in the bricked state at all, because pnpm refuses at command startup and `preinstall` never runs, so a colleague cloning into the pairing still gets pnpm's own message blaming their Node. What it does catch is the pairing on the machine of whoever introduced it while already sitting on the pinned Node — the one state where the configuration is silently latent, and the cheapest place it will ever be fixed. Absent `devEngines` is deliberately not a failure: that is the musl posture v1.0.1 documents, where `engineStrict` is the only Node enforcement the project has and must stay on, so only the pairing fails. The `.npmrc` spelling is checked alongside the `pnpm-workspace.yaml` one because it predates pnpm's move of settings into the workspace file, is still honored, and deadlocks identically — a missed spelling here fails toward a silent brick. Verified against a seven-case battery covering both directions: the pairing under each spelling, `engineStrict: false` with `devEngines`, `engineStrict: true` with no `devEngines`, a commented-out key, an absent `pnpm-workspace.yaml` and `.npmrc`, and a regression confirming the pin-drift check still fires ahead of it.
- **Adaptation notes**: An instance already past v1.0.1 checks its own `pnpm-workspace.yaml` and `.npmrc` for `engineStrict` / `engine-strict` right now, since a repo bricked this way looks like a machine problem and stays misdiagnosed until someone reads the ambient Node in the error. An instance that never set the key needs no config change and takes only the guard. An instance that genuinely wants dependency-engine blocking more than it wants the runtime download takes the second branch the guard offers, deleting `devEngines` and requiring every contributor to install the pinned Node themselves; both postures are supported, and only holding both at once is refused. An instance whose `engineStrict` sits somewhere the guard does not read — a nested workspace file, a user-level `.npmrc`, a `NPM_CONFIG_ENGINE_STRICT` environment variable — extends `engineStrictSite()` to that site rather than reporting the miss as a false negative. ## v1.0.4 — 2026-07-29

- **What**: Fixes three related defects in how a session reports back to the human. A new `CLAUDE.md` Standards rule governs every session-closing message and every mid-session handoff that expects a reply: one consolidated plain-language summary, one bullet per open item, and a bullet the human decides ends in a direct question with the recommendation and its reasoning attached. `review-board`'s consolidated report format (`references/output-format.md`, Part B) is restructured around that same shape — the verdict table stays, the per-verdict prose sections are replaced by a "Your call" list of plain-language decision bullets each ending in a question, a "Noted, no decision needed" list of one-liners for findings nobody is being asked to decide, and an "Evidence" appendix carrying the excerpt, failure scenario, suggested fix, and chair's read for the decision findings only; the separate "Board recommendation" section is gone, since per-finding recommendations now ride in the bullets that ask the questions. `review-board`'s Step 3 replaces "which are safe to defer" with three provenance-decided dispositions — fix in this session, `/capture-task` naming which of its two grounds applies, or noted-no-action — and Step 4 states the report's decision-first contract and the two rules that hold it. Step 6's record commit gains a `captured` outcome spelling carrying the task file path. The skills README blurb and a new tracker fork-point follow.
- **Why**: A closing message that announces "two things want your call" and then asks nothing is unanswerable — the reader cannot tell a question from a status note, and the reply they were supposed to give has no shape. The rule is written as the positive act (name the response each bullet invites; rewrite or cut the ones inviting none) rather than as a ban on status dumps, because the failure is a missing question and not an excess of prose. It lands in `CLAUDE.md` Standards rather than a `.claude/rules/` file because it governs conversational output, which no path can scope: `.claude/rules/` is defined throughout this repo as path-scoped rules, and its only current occupant is `template-dev.md`, which `project-init` deletes — a closing-message rule filed there would ship to zero instances. The review-board half is the same defect in the one format where it is most expensive: the report was ordered by provenance (grouped by verdict, full evidence block per finding), so answering "which findings should I address?" meant reading every excerpt and failure scenario and reconstructing the decision from them, with the actual recommendation deferred to a 3-6 line block at the bottom. Ordering by what the human does with it inverts that, and the property the layout now holds explicitly — answer the closing question from the first screen without reading a code excerpt — is what every judgment about placement is made against. Evidence is appended rather than collapsed because Claude Code renders reports in a terminal, where a `<details>` block does not collapse; omitting it for "Noted" findings costs nothing, since the Step 6 record commit carries the full set to the branch regardless. The deferral posture was backwards in a way that compounds: a finding got recommended for `/capture-task` because its fix looked like a bigger change, including when the session's own work caused it, which is exactly the case where the session holding the change's context is the cheapest place the defect will ever be fixed — deferring buys a full context rebuild in a future session on top of the same fix. Size is therefore explicitly disqualified as grounds, and `/capture-task` narrows to two named cases, a pre-existing bug whose root cause needs investigation this change has no grounds to run or a design tradeoff deserving its own decision, with the recommendation stating which. Naming `/capture-task` as a destination is new coupling, hence the tracker fork-point. One stale claim in the README blurb is corrected while adjacent: it said the chair "verifies each against the actual code", which contradicts Step 3 — triage judges from context and defers deep verification to the findings the human selects.
- **Adaptation notes**: The `CLAUDE.md` rule is one bullet in Standards, taken verbatim or reworded to the instance's register; an instance whose sessions close through a fixed template (a PR body, a ticket comment) states that surface as the point-of-use exception rather than dropping the rule. An instance that added report sections of its own (compliance attestations, a sign-off block) places them below "Process notes" and above the evidence appendix, since the decision bullets own the first screen by construction. Instances whose captures live in a tracker rather than `docs/tasks/` name that destination in Step 3 per the new fork-point. An instance under a compliance regime that requires full evidence in every report keeps the appendix but extends it to the "Noted" findings too, rather than reverting the ordering — the ordering is what makes the report answerable, and the appendix is where length belongs either way.

## v1.0.3 — 2026-07-29

- **What**: Fixes two independent defects in the `guard-context-edit` hook. Governance is now scoped to the repository — a gated file must sit under `$CLAUDE_PROJECT_DIR`, the session's cwd, or `~/.claude`, or else share a git common directory with the session's checkout, with `node_modules` and `~/.claude/plugins/` carved back out — and a subagent's skill-load marker now resolves against the root session transcript as well as the agent's own, so a session that loads `curate-context` or `domain-modeling` before it delegates covers the agents it spawns. A load is now recognized as a structured transcript record rather than as a substring: an assistant `tool_use` block named `Skill`, or one of the two shapes a slash command is recorded in. Paths are canonicalized through `realpath` before any comparison, each transcript is scanned separately instead of concatenated, and a transcript that exists but cannot be read now fails open rather than blocking. The `CLAUDE.md` bullet describing the gate is rewritten in place to carry the inheritance affordance, so a session knows to load the owning skill before delegating rather than discovering it from a blocked edit.
- **Why**: the hook matches on basename, and a basename belongs to no project, so nothing stopped it from following a session off the repo: a throwaway `CONTEXT.md` in the session scratchpad, a `/tmp` note named `architecture.md`, a `README.md` in an unrelated checkout, and every vendored `node_modules/*/README.md` all blocked and demanded a full curation session for a file no context discipline governs — the scratchpad case being the one that fires daily, since sessions are instructed to put temp files there. Scoping by containment alone proved to be the wrong shape twice over, and both corrections came out of a review board on the first attempt. A worktree is a _sibling_ of the main checkout under `$HOME/Code/.worktrees/<project>/<branch>`, not a child, so lexical roots leave the other checkout of the same repository ungated — reproduced by executing both revisions against one `CLAUDE.md` write from a main checkout into its worktree, blocked before the change and allowed after, which is precisely the state `implement-task` occupies between `gwt-add.sh` and `EnterWorktree`. Git identity settles it without shelling out: a main checkout has a `.git` directory, a worktree has a `.git` file pointing at `<main>/.git/worktrees/<name>`, and both reduce to the same common directory, so two checkouts of one repository are one governance domain while an unrelated checkout stays released. Separately, `path.resolve` is purely lexical, so the canonical spelling the session reports for its cwd (`/private/tmp/...` on macOS) and the symlinked spelling a model may write (`/tmp/...`) compare unequal and drop governance for an entire tree; `realpath` on the longest existing prefix fixes that while still admitting a `Write` to a file that does not exist yet. The subagent half was invisible from the code: Claude Code writes each subagent's conversation to its own file beneath `<dir>/<session-id>/subagents/` while the session's own transcript is `<dir>/<session-id>.jsonl`, and the hook read only the path handed to it, so an orchestrator's skill load was unreadable to every agent it spawned. Confirmed against a real board run whose session transcript carries three skill markers and whose five subagent transcripts carry none, and by executing the hook on one `CLAUDE.md` edit twice: exit 0 under the session transcript, exit 2 under the subagent's. Any delegated wave whose payload is context edits therefore could not run at all. The escape hatch was worse than the block — a subagent can call the Skill tool and the marker does land in its own transcript (verified against an agent that loaded `tdd`), but `curate-context` and `domain-modeling` are human-in-the-loop disciplines and a subagent has no human to gate on, so self-loading satisfies the guard by discarding the thing it protects; agents whose tool list omits `Skill` had no recovery at all and simply burned turns retrying a denied edit. The derivation pattern must not pin the segment count after `subagents/`: a directly spawned agent sits at `subagents/agent-<id>.jsonl` but a workflow-spawned one sits at `subagents/workflows/wf_<id>/agent-<id>.jsonl`, and a pattern matching only the flat shape left the defect live for the workflow case — 212 of the 1,010 subagent transcripts on the development machine, or 21%, and exactly the delegation shape most likely to carry a wave of context edits. The corrected pattern derives an existing root session for all 1,010, and derives into `subagents/` for none of them, so a sibling agent's transcript is still never read directly. Reading the root session transcript also forced the marker itself to get stricter, because substring matching cannot tell a load from a mention and the widening would otherwise have spread every false-pass across a whole session: writing this guard's own test fixture — a file whose text contains `<command-name>/curate-context</command-name>` — put that string in the session transcript and switched the guard off for the remainder of that session. A load is therefore matched as a record now, which rejects file content, tool results, and quoted examples because each rides inside a record of some other shape. Both slash-command shapes must be accepted: built-in CLI commands are a `system` record with subtype `local_command`, while skill and custom commands are a `user` record whose `message.content` is a plain string, and a first pass that handled only the former would have stopped detecting every slash-command load and blocked the sessions that used one. Checked by replaying both the old and the new detection over all 1,397 transcripts on the development machine against eleven skill names: the structural check never fires where the textual one did not (so nothing is newly licensed), it detects 291 slash-command loads the record-only-`system` version would have missed, and the twelve textual matches it now rejects are all mentions rather than invocations. Two costs were fixed while the file was open: joining both transcripts before scanning allocated a second full copy of an append-only log that grows without bound (measured at roughly 28ms for a real 3.5MB+1.0MB pair and 97ms for a 15MB pair, against a process-spawn floor of 30-50ms), and swallowing every read error alike meant an `EACCES` on the root transcript — the only source that can carry an orchestrator's marker — blocked an edit the session was entitled to make, contradicting the fail-open posture the file's own header promises. Verified against 55 cases covering both directions, including both subagent layouts, both sibling-checkout directions, both slash-command shapes, a command tag quoted inside a Write payload, a symlinked spelling of a governed tree, an unreadable root transcript, a directory whose name merely prefixes the project root, the `docs/adr/`-before-`README.md` arm ordering, and all three fail-open edges.
- **Adaptation notes**: instances carrying the shipped hook take the new file wholesale. One behavior widening deserves a deliberate look: subagents can now edit context files whenever the spawning session loaded the owning skill, and an instance that wants delegated context edits forbidden outright drops the `transcriptsToSearch` derivation and keeps reading only `input.transcript_path`, accepting that such waves cannot run. Structural marker detection is the one change that can newly _block_ rather than newly allow, and it depends on transcript record shapes rather than on file text, so an instance running a Claude Code version that records a `Skill` invocation or a slash command differently sees legitimate loads stop being recognized; the check to run before adopting is a replay of both detections over that machine's own transcripts, confirming the structural one still fires everywhere a real load happened. An instance that keeps context docs in a genuinely separate checkout — a shared docs repository mounted elsewhere, with its own `.git` — adds that location to `GOVERNED_ROOTS`, since neither containment nor git identity reaches it; a `CLAUDE.md` symlinked in from a dotfiles repository needs nothing, because the link is edited through its in-repo path and canonicalization keeps it governed. Instances that forked the hook apply the changes by hand: the containment block belongs after the family dispatch rather than before it, so that an edit forwarded by the prefilter on a content match exits without touching the filesystem. Two vendored paths are excluded, `node_modules` and `~/.claude/plugins/` — the latter because admitting `~/.claude` whole to reach the user-global `CLAUDE.md` also swept in the marketplace and plugin-cache trees, 1,883 `README.md` files and 6 `CLAUDE.md` files on the development machine, none of them written by the project asked to curate them. Instances that commit generated `README.md` files under `dist/`, `build/`, or a vendored directory extend that list rather than reporting the block as a bug. Unchanged in this release: the `settings.json` prefilter still forwards on a literal case-variant list, so spellings outside it (`Context.md`, `Ui_Ux.md`, `docs/ADR/`) never reach the hook and stay ungated on case-insensitive filesystems — a pre-existing hole this release does not close. Closed in v1.0.6, which deletes the prefilter outright; the real count was six spellings, not three. An instance applying v1.0.3 and v1.0.6 in the same sitting takes the v1.0.3 hook body and skips the prefilter half of this note, since v1.0.6 removes the prefilter it describes.
