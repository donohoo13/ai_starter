# Template development rules (ai_starter only)

These rules govern AI sessions developing the `ai_starter` template repository itself. In a project created from the template this file is residue with no authority: delete it.

- This repo IS the template: the whole tracked tree is the payload GitHub copies into new projects ("Use this template" / `gh repo create --template donohoo13/ai_starter`). There is no inner payload directory; editing any file is editing the product.
- Bracketed placeholders (the Company Overview line, Deployment, the `[project]` MCP stanzas) and stack sections for stacks absent here are shipped product content: leave them bracketed and intact; the project that instantiates the template resolves them, never a session here.
- This repo contains no application code and no UI: validation is `pnpm format:check` plus the batteries under `scripts/test/` (the `turbo` tasks no-op on the empty workspace), and the design surfaces (the `.claude/rules/` frontend files) are edited as shipped content, not followed as this repo's own design system.
- Every payload-affecting change lands with a `CHANGELOG.md` entry in the same change: what, why, and adaptation notes for projects that diverged.
- A release is a git tag (`vX.Y.Z`) on `main` matching the entry, published from `main` after the release PR merges, with `package.json` `version` bumped to match.
- Publish as two separate commands, `git tag -a vX.Y.Z` first and `git push origin vX.Y.Z` second: `guard-main` is a PreToolUse hook that evaluates state before the command runs, so batching creation and push into one call blocks on a tag that does not exist yet.
- The `guard-main` hook exempts publishing an existing tag from its default-branch push block precisely so this step stays reachable, while still refusing force, deletes, `--follow-tags`, and any ref that names a branch.
- Version references and cross-release provenance ("removed in vX.Y.Z", "since vX.Y.Z") live only in `CHANGELOG.md` and the dated notes under `docs/notes/`, never in the payload's present-tense steering docs (`CLAUDE.md`, `README.md`, every `.claude/skills/**` file, the `.claude/rules/` files, and hook comments); a change that removes a payload mechanism rewrites the affected doc to the mechanism that exists now and records the what, why, and when in its changelog entry. Grep `v[0-9]` across the payload before tagging a release to catch leaks.
- Propagation is copy-only: a project created from the template reads this repo's changelog and tags and applies what it wants by hand; never push, PR, or hand-apply template changes into a child from a session here, and never reach into a child to diagnose one of its issues. Findings arrive as ordinary GitHub issues against this repo; verify each claim against the current payload before fixing, since the reporter may be several releases behind.
- The template's own working artifacts (`docs/notes/`, `docs/specs/`, `CHANGELOG.md`, this rules file) accrue here as normal project history, so develop freely rather than self-censoring to keep the payload clean.
- `.claude/settings.local.json` on this machine disables every shipped `.mcp.json` server except `context7` via `disabledMcpjsonServers`, since template-dev sessions need none of the others; keep that list in step when adding shipped server stanzas. Machine-personal quirks go in `CLAUDE.local.md` (gitignored); rules that belong to the repo's process live in this file.
